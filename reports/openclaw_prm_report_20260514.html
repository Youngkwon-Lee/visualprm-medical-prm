Implementation Notes

툴을 어디서 붙이고 어디 코드를 쓰나

역할 파일 설명
Agent profile 생성 setup_pathvqa_openclaw_agents.py vision-direct, vision-and-web, image-only 같은 실험용 agent preset과 tools.allow / tools.deny를 생성. 핵심은 build_agents(...).
OpenClaw config openclaw_gemma4_only.json 실제 agent별 모델, system prompt, tool allow/deny가 들어 있는 런타임 설정. tools.allow, tools.deny를 여기서 최종 확인.
Prompt / candidate generation run_openclaw_pathvqa_native.py sample별 prompt 생성, strict step 규칙, majority 집계, session/tool trace 수집까지 담당. 주요 함수: build_prompt(...), allowed_tools_for(...), inspect_session_tools(...).
PRM rerank run_medvisualprm_rerank.py 동료 PRM 모델 SNUH-C/medvisualprm-branch-b를 외부 critic으로 호출해 후보를 점수화.
실험 실행 wrapper run_local_pathvqa_web_prm_full.sh candidate 생성 후 PRM rerank를 순서대로 호출하는 shell wrapper. 여기서 AGENT_ID, VOTES, FULL_VOTES 등을 바꿔 실험 조건을 바꿈.
Quick Ops

툴 켜고 끄는 방법

상황 방법
tool 완전 끄기 vision-direct처럼 agent profile에서 tools.allow = []로 두고, prompt에도 Do not call any tools를 명시. 코드 위치: setup_pathvqa_openclaw_agents.py, openclaw_gemma4_only.json.
web만 켜기 vision-and-web처럼 web_search, web_fetch만 allow하고 image는 deny. 코드 위치: setup_pathvqa_openclaw_agents.py, allowed_tools_for(...).
image tool만 켜기 image-only / image-once profile처럼 image만 allow하고 web는 deny. 코드 위치: setup_pathvqa_openclaw_agents.py.
코드에서 강제 확인 run_openclaw_pathvqa_native.py의 allowed_tools_for(...), required_image_call_count(...), inspect_session_tools(...)가 실제 사용 여부를 검증.

즉 tool 정책은 config에서 1차, prompt에서 2차, 후처리 검증에서 3차로 묶어 둔 구조입니다.

조건 핵심 prompt 요약
vision-direct “이미지 경로는 direct vision으로 보인다. tool은 쓰지 마라. JSON만 반환하라.”
vision-and-web “가능하면 이미지를 먼저 보고 reasoning하되, 필요할 때만 web_search/web_fetch를 써라.”
vision-and-web-no-utah-search 위와 동일하지만 Utah, 파일명, sample-id, dataset 직접 검색을 금지.
strict step steps 3~6개, 첫 step은 Visual evidence:, 마지막 step은 Decision:, plain string only.
v2 diversity 홀수 attempt는 observation-first, 짝수 attempt는 option-elimination-first로 reasoning style을 다르게 유도.
현재까지의 결론은, prompt를 더 엄격하게 만들어도 형식은 정돈되지만 기본 visual read가 틀리면 PRM이 구제하기 어렵다는 점입니다.
Interpretation

현재까지의 해석

질문 현재 답
PRM을 쓴 1147 전체 결과가 있나? 없음. 현재 1147 완주 결과는 모두 PRM 미사용 baseline.
OpenClaw agent 자체가 이득이 있나? 소규모 pilot에서는 같은 10샘플 기준 pathvqa-native-strict = 4/10, pathvqa-web = 10/10으로 web-enabled agent가 훨씬 강했음.
Utah full 97에서는 web가 실제로 이득이었나? 아직 아니었음. vision-direct + PRM = 59/97, vision-and-web + PRM = 55/97, vision-and-web-no-utah-search + PRM = 53/97. Utah 직접 검색 금지를 넣어도 web 사용이 이미지 grounding을 안정적으로 보강하진 못했습니다.
strict step-by-step을 강제하면 나아졌나? 아직 아니었음. 최신 Utah 2문항 smoke에서 vision-direct, vision-and-web, vision-and-web-no-utah-search 모두 0/2였다. 형식 강제만으로는 visual grounding 품질 문제를 해결하지 못했다.
PRM이 바로 성능을 올렸나? 아직은 아님. web 10샘플에선 majority 10/10 → PRM 9/10, native-strict 10샘플에선 overall 3/10으로 개선 없음.
가장 큰 병목은 무엇인가? PRM scoring이 아니라 OpenClaw candidate generation.
현재 데이터만 보면, 가장 안정적인 큰 결과는 no-tool vision baseline이고, 작은 pilot에서는 web agent가 강했지만, Utah full 97에서는 web가 오히려 성능을 떨어뜨렸습니다. 그 이유는 web가 이미지를 보강하기보다 대체해버려 web_search-dominant trace로 흐른 점에 있습니다. PRM은 아직 “성능 향상 장치”라기보다 “검증 중인 critic”에 가깝습니다. 특히 같은 10샘플에서 native-strict actor는 4/10이었고, native-strict + PRM pilot도 3/10 수준이라 critic 이득이 보이지 않았습니다. Utah full 97에서도 no-utah-search 제약은 leakage 완화 의도는 좋았지만, 최종 점수는 53/97로 baseline보다 낮았습니다. 최신 strict-step smoke도 세 조건 모두 0/2라서, 현재 병목은 step 형식보다 기본 시각 해석 품질과 web/output 안정성 쪽에 더 가깝습니다. 추가로 Gemma4 후속 실험에서는 GPT teacher few-shot이 Utah smoke에서 1/2, 다음 2문항에서도 1/2로 작은 개선을 보였지만, format-only 버전은 다시 0/2였습니다. 즉 형식만 GPT처럼 바꾸는 것보다, teacher demonstration 내용이 실제로 더 중요하다는 신호가 나왔습니다. Distillation 없이 올리는 방향으로 multi-view, contrast/zoom, 간단 option check, controlled morphology hint를 묶은 smoke도 실행했습니다. 결과는 전체 2문항 기준으로는 안정적 개선 실패에 가깝습니다. center-zoom 후보가 skin case에서 정답 Thrombocytopenia를 만들고 PRM이 이를 선택한 부분 신호는 있었지만, heart case는 Gemma4 direct 응답이 비어 모든 후보가 invalid였습니다. 따라서 Gemma4를 prompt/controller/전처리만으로 계속 끌어올리는 방향은 일단 중단하고, 다음 단계는 더 적합한 low-B vision actor 비교로 옮기는 것이 맞습니다.
